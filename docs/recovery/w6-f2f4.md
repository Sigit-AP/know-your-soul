## F2 — contract-v3 adapter mapping implemented for real

The frozen mapping (`ingestion-contract-v3.md:126-133`) now exists on all
three surfaces, all calling the existing `IngestionPipeline` — no new
ingestion logic, only adapter validation + contract shaping:

- **Shared adapter helper** (`http_api.run_ingest_verb`): closed key sets
  per verb (`ingest_file`: `path`, `token_budget`; `ingest_directory`:
  plus `recursive`, `max_files`); strict types (bool-is-not-int); the frozen
  budget semantics (`token_budget < 128` → `BUDGET_TOO_SMALL`, `>` configured
  max → `BUDGET_EXCEEDS_MAX`); path discipline against the startup-fixed
  ingestion root (`..`/absolute-outside/symlink escape → `PATH_OUTSIDE_ROOT`,
  missing → `PATH_NOT_FOUND`, unreadable → `PATH_NOT_READABLE`);
  `max_files` pinned to `[1,65536]`.
- **MCP** (`mcp_server.py`): `knowledge_ingest_file` /
  `knowledge_ingest_directory` with closed schemas
  (`additionalProperties: false`), the pinned ranges, and exactly one
  path-like property (`path`) each — the v3 addendum's confined amendment of
  the v2 no-path rule. `ToolError` gained `already_journaled` so a
  pipeline-journaled failure is never double-audited. The ingestion root is
  the startup `--graph-root`.
- **HTTP** (`http_api.py`): `POST /v1/knowledge/ingest/file` and
  `POST /v1/knowledge/ingest/directory`, inside the same
  `BoundaryMiddleware` (Host allowlist + API-key + streaming body cap) and
  the same JSON-content-type CSRF guard as every other POST route. The
  ingestion root is the stack's `ops_root`. Typed pipeline codes map to
  honest statuses (`PATH_NOT_FOUND` 404, `FILE_TOO_LARGE` 413,
  `UNSUPPORTED_MEDIA_TYPE` 415, budget codes 400, ...). The verbs are **not**
  members of `KNOWLEDGE_OPERATIONS`/`OPS_OPERATIONS` — the frozen fourteen
  are untouched.
- **CLI** (`cli.py`): `ingest-file` / `ingest-directory` aliases per the
  mapping; the existing ops `ingest` is unchanged. The CLI's fixed ingestion
  root is the process working directory; stdout carries the canonical JSON
  proposal, typed failures the standard envelope on stderr (exit 1).
- **Output budget shaping** (contract-mandated adapter behavior):
  `ingest_file` is atomic — a response over `token_budget` fails typed
  `METADATA_EXCEEDS_BUDGET`; `ingest_directory` truncates `files`
  tail-first with `truncated: true`, envelope keys never truncated.
  Token estimation reuses the frozen `estimated_tokens_of_payload`
  (ceil(utf8/4) of the canonical payload).

**Audit discipline**: exactly one final audit event per invocation named
`knowledge.ingest_file` / `knowledge.ingest_directory` — the pipeline
journals every invocation it runs; the adapter journals one failure event
under the same name for pre-pipeline rejections (closed-key/type/range,
budget bounds, path escapes); `METADATA_EXCEEDS_BUDGET` carries the
pipeline's own `audit_event_id`. Verified by counting `event_log` rows per
invocation in the new tests.

## F3 — primary-containment invariant enforced

- `graph_model.py`: new typed errors `InvalidBridgeEndpointError(BridgeError)`
  with `code = "INVALID_BRIDGE_ENDPOINT"` (the code the frozen contract names
  for a non-primary bridge endpoint — now present in code, raised by
  `_check_bridge`) and `PrimaryContainmentError(GraphModelError)` with
  `code = "PRIMARY_CONTAINED_BY_PRIMARY"`.
- `_check_contains` is kind-aware: a `contains` edge whose **both** endpoints
  are primary is rejected eagerly at `add_edge`. `validate()` re-proves the
  same invariant (defense in depth). Legitimate shapes are unaffected and
  pinned by tests: primary → non-primary contains (a primary rooting an
  arbitrarily deep hierarchy), non-primary → primary contains, bridges
  between primaries.
- Contract note: the v3 addendum names no error code for the
  primary-containment invariant (only the invariant itself), so
  `PRIMARY_CONTAINED_BY_PRIMARY` is the introduced typed code, recorded here
  per the amendment rule (the contract is not *wrong* — the invariant was
  stated without a code; no contract text was amended).

## F4 — resolver failure reasons persisted (schema v4)

- `store.py`: `SCHEMA_VERSION` 3 → 4; `_SCHEMA_V4_STATEMENTS` =
  one additive `ALTER TABLE unresolved_refs ADD COLUMN failure_reason TEXT`,
  applied transactionally and recorded in `schema_versions` (idempotent
  across reopens; a failed migration rolls back and leaves no trace —
  proven by test). Consistency stays fail-closed both directions: v4
  recorded without the column → `SchemaStateError`; the column without a v4
  record → `SchemaStateError`; any missing ledger row in `3..recorded` →
  `SchemaStateError` (the pre-existing v3 disagreement test passes
  unchanged).
- `record_resolution_attempt(ref_id, outcome=..., reason=...)`: persists the
  deterministic reason on `failed`, clears it on `resolved` (terminal state
  is clean), rejects a reason on `resolved` and non-string/empty reasons
  (fail-closed). `retry_failed_ref` preserves the last reason for audit
  while the ref is pending again.
- `resolve/resolver.py`: `resolve_pending` passes `decision.reason` to the
  store and builds each `RefOutcome.reason` **from the persisted row** —
  the `BatchReport` is a read of the store, not of in-memory decisions.
- `UnresolvedRefRow.failure_reason: str | None`; old rows migrate to NULL.
- Pre-existing determinism surfaces (`canonical_ingestion_dump`) include the
  new column via `SELECT *`; two identical runs remain byte-identical (the
  reasons are deterministic strings) — full determinism suites stay green.

## Contract decisions (no amendment was needed)

1. `ingest_file` on a directory (or `ingest_directory` on a file) fails typed
   `PATH_NOT_FOUND` ("not a regular file" / "not a directory") — the contract
   names path discipline codes only; a wrong-kind path is "no such
   file/directory". Recorded here.
2. `max_files` outside `[1,65536]` fails `VALIDATION_ERROR` (HTTP/CLI) /
   `INVALID_ARGUMENTS` (MCP schema bounds) — the contract pins the range but
   names no code; this matches the documented D5 adapter difference
   (`arch-review-F2-adapter-validation-parity.md`: MCP guides with schema
   bounds, HTTP/CLI raise typed errors).
3. The v3 tables are the proposal staging the pipeline already owns; the
   adapter layer changes none of that (pipeline untouched, per scope).
4. The pipeline keys the v3 `files`/`symbols` tables by its derived root
   (the parent directory of a single-file input); the adapter re-anchors
   only the contract envelope's `input.path` to the startup-fixed ingestion
   root. Per-file entries stay relative to the walked directory, as the
   contract's traversal rule defines.
