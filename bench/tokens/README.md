# bench/tokens/ — token-reduction benchmark (SUB-108, wave 8)

Honest, deterministic, no-AI measurement of the product's token reduction:
**raw corpus tokens vs the tokens retrieval actually needs to answer a frozen
question set.** Mixed corpus (multi-language code + markdown + text + small
PDFs), sha256-pinned and vendored offline under `corpus/`.

## Layout

| Path | What it is |
|------|------------|
| `run.py` | The harness: `freeze`, `verify`, `check`, `run` subcommands |
| `data/corpus.tar.gz` | Vendored corpus pool (52 files) as a canonical, byte-reproducible archive (same pattern as `bench/codebase`): code from the pinned `bench/codebase` repos (requests v2.32.4, chalk v5.6.2, tree-sitter-python v0.23.6), markdown docs (incl. 5 SOUL files from `bench/corpus`), tree-sitter corpus texts, and 5 deterministic "paper notes" PDFs generated byte-identically by `run.py` (`make_pdf_bytes`) |
| `manifest.json` | Archive sha256 + per-file sha256/size pins, tier membership |
| `questions.json` | Frozen questions per tier with rubric terms, source files, and one negative control per tier |
| `results/` | Machine-readable JSON ledgers + markdown reports, one per `run` |

## Commands

```bash
uv run python bench/tokens/run.py freeze   # regenerate PDFs + manifest (offline)
uv run python bench/tokens/run.py verify   # corpus integrity vs manifest
uv run python bench/tokens/run.py check    # no-corpus self-checks (exit 0/1)
uv run python bench/tokens/run.py run      # full measurement -> results/
```

## What is measured

* **Raw tokens**: `ceil(utf8_bytes / 4)` per file (the frozen contract
  estimator, `know_your_soul.contracts.estimated_tokens_of_payload`),
  summed over the tier.
* **Query tokens**: for each frozen question, the product retrieval runs
  as-is — `SymbolLookup` (FTS5 → LIKE → fuzzy) at top-10, then
  `assemble_context` with a 2000-token budget (Graphify's MCP default) — and
  the question text plus the rendered context are measured with the same
  estimator.
* **Reduction**: `raw_tokens / mean_query_tokens`. The mean INCLUDES the
  negative-control question (a no-match answer still costs the context
  frame) — Graphify's harness excludes no-match questions from its average,
  which flatters the ratio.
* **Rubric coverage**: fraction of each question's rubric terms present in
  the assembled context (case-folded substring). The product returns
  symbol/section identities with provenance, never raw bodies — so rubric
  terms are names/headings/paths a sufficient answer must carry.

## Per-tier honesty

Tiers are nested (small 6 ⊂ medium 26 ⊂ large 52 files) because token
reduction scales with corpus size; all three are reported, including the
small tier where the reduction is modest — a handful of files barely needs
a graph.

## The Graphify 71.5x reference (context only, never a gate)

Graphify documents **71.5x** on THEIR corpus (Karpathy repos + 5 papers +
4 images, 52 files, ~92,616 words → ~123,488 naive tokens, ~1,726 avg query
tokens; sources: `docs/how-it-works.md`, `worked/karpathy-repos/review.md`
in Graphify-Labs/graphify). Differences that make this NOT a like-for-like
comparison: different corpus content, different corpus estimator
(words×133/100 vs bytes/4), different retrieval product (BFS subgraph text
with rationale vs skeletonized symbol entries), and their average excludes
no-match questions. The number is recorded in every ledger under
`graphify_reference` with these caveats; our tiers stand on their own.

## Gates (`run` exits 0 only when all hold)

1. corpus verifies against the pinned manifest;
2. determinism: two ingest passes per tier byte-identical
   (`canonical_ingestion_dump`) AND two query passes produce identical
   per-question results (hits, tokens, coverage);
3. retrieval recall: every positive question retrieves ≥ 1 hit, every
   negative control retrieves none;
4. rubric: mean coverage per tier ≥ `RUBRIC_FLOOR` (0.5, fixed constant).

Exit codes: 0 pass, 1 gate failure, 2 usage error.
